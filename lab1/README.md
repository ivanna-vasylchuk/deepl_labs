# ЛР1. Backpropagation на NumPy

## Запуск

Python 3.12, NumPy, PyTorch (CPU), scikit-learn. Пакетний менеджер — `uv`. Усі обчислення у `float64`.

```bash
uv run python main.py          # правильна реалізація
uv run python main.py --bug    # дослід із помилкою
```

Таблиці зі значеннями пишуться у `results/`.

## Дані та ініціалізація

- Iris: 150 об'єктів, 4 ознаки, 3 класи. Стратифікований поділ 70/30: з кожного класу 35 об'єктів у train і 15 у test (train — 105, test — 45).
- Стандартизація: `mean` і `std(ddof=0)` рахуються лише на train, застосовуються до обох частин.
- Ваги: спільний `rng = np.random.default_rng(0)`, спочатку `W1` (He, σ = √(2/4), форма `(4, 8)`), потім `W2` (Xavier, σ = √(2/11), форма `(8, 3)`), зсуви — нулі.

У NumPy ваги мають форму `(in, out)`, у PyTorch `nn.Linear` — `(out, in)`, тому при копіюванні ваги транспонуємо.

## Формули backward

Архітектура: `X → Linear(4, 8) → ReLU → Linear(8, 3) → logits`. Втрата — усереднена крос-ентропія `L = −(1/N) Σ Y ⊙ log P`.

Сигнали похибки:

- `Δ2 = (P − Y) / N`
- `Δ1 = (Δ2 @ W2.T) ⊙ mask`,   `mask = (Z1 > 0)`

Градієнти:

- `∇W2 = A1.T @ Δ2`
- `∇b2 = sum_axis0(Δ2)`
- `∇W1 = X.T @ Δ1`
- `∇b1 = sum_axis0(Δ1)`

Множник `1/N` з'являється лише в `Δ2` — далі він переноситься ланцюговим правилом.

## Розмірності

| Величина | Форма |
|---|---|
| `X` | `(N, 4)` |
| `Z1 = X @ W1 + b1` | `(N, 8)` |
| `A1 = ReLU(Z1)` | `(N, 8)` |
| `Z2 = A1 @ W2 + b2` | `(N, 3)` |
| `P = softmax(Z2)` | `(N, 3)` |
| `Δ2 = (P − Y) / N` | `(N, 3)` |
| `Δ1 = (Δ2 @ W2.T) ⊙ mask` | `(N, 8)` |
| `∇W1` | `(4, 8)` |
| `∇b1` | `(8,)` |
| `∇W2` | `(8, 3)` |
| `∇b2` | `(3,)` |

## Кеш

| Значення | Навіщо |
|---|---|
| `X` | входить у `∇W1 = X.T @ Δ1` |
| `mask` | множник ReLU у `Δ1` |
| `A1` | входить у `∇W2 = A1.T @ Δ2` |
| `P` | стартовий сигнал `Δ2 = (P − Y) / N` |

## Чисельна перевірка

## Дослід із помилкою (`--bug`)

У `backward()` при `bug=True` прибрано ділення на `N` у `Δ2`.

**Прогноз (до запуску):**

- Втрата не зміниться — `1/N` сидить у `L`, а `Δ2` до втрати не входить.
- Усі ненульові градієнти зростуть у `N = 105` разів — множник переноситься ланцюговим правилом однаково.
- Обидві перевірки виявлять помилку.

**Фактично:**

Втрата NumPy = Втрата PyTorch = `1.4562007801142818e+00` — не змінилась.

## Висновки

1. Ручний backprop збігається з PyTorch до рівня заокруглення `float64` (`≤ 1.25e-16`) і з центральною різницею з точністю ~2.4e-10.
2. Множник `1/N` ставиться рівно один раз — у `Δ2`. Якщо його забрати, втрата не зміниться, а всі градієнти масштабуються в `N` разів.
3. При `ε = 1e-6` маска ReLU стабільна для всіх перевірених параметрів, тож центральна різниця не перетинає злам.
4. Збіжність втрати нічого не гарантує — виявляють помилку саме перевірки градієнтів.
